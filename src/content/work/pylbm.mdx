## Problem

<p class="lede">Fluid simulation is easy to make look right and hard to make be right.</p>

A square box of fluid, a lid that slides across the top, three walls that hold still: the lid-driven cavity is about the simplest flow there is, and that is exactly why it matters. Since Ghia, Ghia and Shin published their tables in 1982, it has been the test a new incompressible-flow solver has to pass before anyone trusts it with anything else.

pylbm is a solver built to pass that test, and to do it on a GPU.

## Constraints

- **Correctness first.** The output has to line up with published reference data, not just produce a convincing vortex.
- **One GPU.** The full lattice and its velocity populations have to live in GPU memory at once.
- **Two dimensions, nine velocities.** The D2Q9 model: every lattice node carries nine populations, one at rest and eight moving to its neighbours.
- **Python on the GPU.** Written with PyTorch, which runs the arithmetic on the GPU through CUDA.

## Approach

Lattice-Boltzmann does not solve the Navier–Stokes equations directly. It tracks populations of fluid particles on a grid and alternates two simple moves: a **collision**, which relaxes every node towards local equilibrium, and a **stream**, which shifts each population one node along its direction. Walls and the moving lid enter as boundary conditions. Repeat for enough time steps, and the macroscopic flow emerges.

Both moves are the same operation applied to every node at once. Written as PyTorch tensor operations, that is exactly the shape of work a GPU is built for.

## Decisions

<div class="decisions">
  <Decision chose="Lattice-Boltzmann" over="a finite-difference Navier–Stokes solver">
    Every update in LBM is local: a node only needs itself and its eight neighbours. That makes the method naturally parallel, which is the whole point of running it on a GPU.
  </Decision>
  <Decision chose="PyTorch" over="a separate GPU code base">
    Collision and streaming are written as operations on whole tensors, and PyTorch runs them on the GPU through CUDA. The numerics stay in Python, next to the code that sets up and checks the run.
  </Decision>
  <Decision chose="The lid-driven cavity" over="a flow without reference data">
    A benchmark with published numbers turns "looks plausible" into a comparison that can fail. That is the only kind of result worth reporting.
  </Decision>
</div>
