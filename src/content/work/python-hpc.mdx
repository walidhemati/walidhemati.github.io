## Problem

<p class="lede">Is Python a GPU language, or only the thing that launches one?</p>

Triton, NVIDIA Warp and Numba-CUDA let the kernel itself be written in Python, and `torch.compile` turns array code into fused GPU kernels. Whether that is fast enough for scientific computing is usually argued with a single number. A fair answer needs the same algorithm in every language, a ceiling that says what the hardware allows, and real HPC codes on the same machine.

## Approach

Six packages, each a complete, validated simulation code with its own paper:

- **[pylbm](/work/pylbm/)**: lattice Boltzmann flow (D2Q9, D3Q19).
- **[pyheat3d](/work/pyheat3d/)**: heat equation and Jacobi stencils, with temporal blocking.
- **[pygravity](/work/pygravity/)**: direct-summation N-body gravity.
- **[pymd](/work/pymd/)**: Lennard-Jones and EAM molecular dynamics.
- **[pyspectral](/work/pyspectral/)**: pseudo-spectral Navier–Stokes turbulence.
- **[pyising](/work/pyising/)**: Ising Monte Carlo with 1-bit multi-spin coding.

Every package implements the same optimisation ladder and checks every rung against a NumPy oracle:

## Decisions

<div class="decisions">
  <Decision chose="Percent of a measured roofline" over="raw speed-ups">
    A speed-up says nothing about how much is left. Every number is reported against a ceiling measured on the same GPU: copy bandwidth, FMA throughput, cuFFT time or random-number throughput.
  </Decision>
  <Decision chose="Running the established codes myself" over="quoting published numbers">
    FluidX3D, LAMMPS, HOOMD-blue, AN5D, NVIDIA's ising-gpu and six more were built from pinned commits and checked to solve the same problem before timing them on the same GPU.
  </Decision>
  <Decision chose="Every number generated from results files" over="hand-typed tables">
    Benchmarks write JSON; scripts turn it into the papers' numbers, figures and README tables. Final numbers come from serial runs on an idle GPU.
  </Decision>
</div>

## Results

<Results metrics={frontmatter.metrics}>
  Python-language kernels match hand-written CUDA C on lattice Boltzmann, stencils and N-body, and stay within 9–23 % on MD, Ising and spectral. Against the established codes they tie FluidX3D, run 1.3× HOOMD-blue and 1.5× NVIDIA's optimised Ising code; the one loss is AN5D's deep 2D temporal blocking. Details and every caveat are in the [overview paper](https://github.com/walidhemati/pyhpc-overview/blob/master/paper/paper.pdf).
</Results>
